## Context Engineering File Standards

To achieve zero-error agentic development in 2026, repositories must provide standardized instruction files. These files guide AI coding assistants, IDE extensions, and CLI agents, preventing errors and infinite loops.

### 1. `AGENTS.md` (The Cross-Tool Open Standard)
Read by almost all agentic CLI tools (Cline, Aider, Claude Code, Windsurf, etc.), `AGENTS.md` is the universal source of truth for the codebase structure, permissions, and tool usage constraints.

**How to structure it:**
- **Project Context:** Define the tech stack, databases, and general architecture.
- **Agentic State Boundary:** Define which directories the agent is permitted to read or write to (e.g., read-only `.agents/`, write-only `src/`).
- **Command Permissions:** List exact commands the agent can run safely (e.g., `npm test`, `git status`) and mutating commands that require explicit user approval (e.g., `rm -rf`, `npm install`).
- **Development Workflow:** Outline step-by-step instructions for implementing features (checking files before writing, running tests after editing, linting before completion).

### 2. `CLAUDE.md` (For Anthropic Claude Code)
Andrej Karpathy popularized `CLAUDE.md` for Anthropic's Claude Code CLI. It acts as an operational reference card containing build, test, and style configurations.

**How to structure it:**
- **Overview:** One-sentence project description.
- **Build and Run Commands:** Exact commands to install packages, build targets, and run local servers.
- **Test Commands:** Exact commands to run all tests, single tests, or test coverage.
- **Coding Guidelines:** Core guidelines including strict type safety directives and style references.
- **Single Source of Truth Advice:** Advise the agent to refer directly to `.eslintrc` or a shared `STYLE.md` rather than duplicating style rules inside the markdown itself.

### 3. `.cursorrules` & `.cursor/rules/*.mdc` (For Cursor)
Cursor uses `.cursorrules` (in the root) or modular `.cursor/rules/*.mdc` files (enabled per-directory since late 2025) to instruct its Composer and tab-completions.

**How to structure it:**
- **Tech Stack Rules:** Concrete version numbers and frameworks (e.g., React 19, Next.js 16).
- **Coding Standards:** Component design rules, import path syntax, and state management constraints.
- **Style Rules:** Directive to fetch linting and formatting specifications from `.eslintrc` / `STYLE.md` to prevent configuration drift.
- **AI Behavior:** Directives instructing Composer to only provide code diffs or targeted changes, and avoid re-writing entire files for minor updates.
